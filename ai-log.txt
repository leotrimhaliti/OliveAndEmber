The goal is to demonstrate technical knowledge, clear code organization, problem-solving, and thoughtful use of AI. The app does not need to be production-ready. Keep it straightforward, polished, and easy for me to understand and explain.

Required stack:
- PHP / Laravel backend
- React frontend
- MySQL database
- REST API connecting frontend and backend
- Git for version control

Required features:
1. Registration and login.
   - The brief explicitly requires administrator registration and login.
   - Support customer accounts for placing and viewing personal orders.
   - Make administrator registration safe: use an invitation code or another simple protected approach, and explain it. Public registration must not allow anyone to select the admin role.
2. Browse food products with name, description, price, image, and availability.
3. Browse and filter products by category.
4. Add products to a cart.
5. Update quantities and remove cart items.
6. Create an order through a checkout form.
7. View the logged-in customer’s order history and order details.
8. Display order status: pending, preparing, out for delivery, completed, or cancelled.
9. A simple admin dashboard to:
   - Add, edit, and delete or deactivate products.
   - Assign products to categories.
   - View orders and their details.
   - Update order statuses.

Scope and implementation:
- Use a single repository with clearly separated backend and frontend directories.
- Use Laravel’s standard conventions and a simple React structure.
- Choose a suitable Laravel authentication approach, such as Sanctum, and explain the choice.
- Protect admin routes on the backend and ensure customers can only access their own orders.
- Validate requests and return consistent API errors.
- Calculate order totals on the server using database prices; never trust prices or totals sent by the frontend.
- Store the purchased product name and unit price in each order item so historical orders remain accurate after product edits.
- Use a database transaction when creating an order.
- Handle monetary values safely.
- Persist the cart across refreshes using a simple approach.
- Include loading, empty, validation, and error states.
- Build a clean, responsive interface that works on desktop and mobile.
- Include migrations, realistic seed data, and clearly documented local demo accounts.
- Use image URLs or local placeholder assets unless uploads are easy to add without expanding the scope.
- No payment gateway, maps, real-time tracking, microservices, or unnecessary abstractions.

Suggested pages:
- Menu with category filters
- Register and login
- Cart and checkout
- My orders
- Order details
- Admin product management
- Admin order management

Testing:
Add focused tests for the important behavior:
- Authentication and administrator access control
- Customers cannot access other customers’ orders
- Product validation
- Order creation and server-side total calculation
- Invalid quantities and unavailable products
- Administrator order-status updates

Deliverables:
1. Working application code.
2. A README containing:
   - Prerequisites and actual framework/runtime versions used
   - Database setup
   - Environment variable configuration
   - Exact installation, migration, seeding, and startup commands
   - Demo credentials
   - How to run tests
   - API endpoint overview
   - Key architecture decisions and assumptions
   - Known limitations
3. A short submission-ready description of the solution.
4. A practical checklist for publishing the repository to GitHub or GitLab.
5. An AI_USAGE.md explaining how AI helped and how I verified the results.

Start with the architecture, schema, API routes, and plan, then proceed with implementation.
